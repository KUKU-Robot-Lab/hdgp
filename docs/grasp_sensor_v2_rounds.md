**목적.** 09.03 코드 정리에서 실험 스위치 22 종과 기각된 분기를 코드에서 걷어냈다.
지워진 것은 코드지 **지식이 아니다** — "이건 이미 해봤고 이렇게 실패했다"를 여기 남긴다.
되살리려는 생각이 들면 먼저 여기를 읽을 것.

**확정 정책.** `v2E29_band80_ep4000.pth`

⑤ 성공 **99.6%** · 접근각 **97.9°** · 판 위 20 mm 아래로 내려간 env **0.8%** ·

## ★가장 비싼 교훈 — 접근각은 자세 문제가 아니라 **파지 높이** 문제였다

목표: 접근 중 TCP z 가 world z 와 수직(90°)이 되게. 실측 출발점은 **118°**(아래로 기욺).

**전부 실패한 8 종:**

| # | 시도 | 결과 |
|---|---|---|
| 1 | 순수 벌점 `approach_tilt_penalty` | 90° 이하가 전 구간 0 → 정책이 그리퍼를 위로 세워 벌점만 피하고 **파지 포기** |
| 2 | 레벨 보상 `approach_dir_bonus` (w 7.0) | 각도는 117.5° → 90.1° 로 내려갔지만 250 스텝 중 239 스텝을 **떠 있기만** 함. ⑤ 0.0% |
| 3 | 같은 항 w 2.0 (I2) | `az<0` 이 **값도 기울기도 0 인 평지** → 110° 에 자리잡은 뒤 1000 epoch 미동 없음 |
| 4 | PBRS(차분 지급) | 차분은 정의상 **최적 정책을 바꾸지 않는다** — 도구 선택 오류 |
| 5 | 곱셈형 방향 `dirmul` | 레벨 지급의 이분법은 피했으나 각도가 안 움직임 |
| 6 | 홈 교체 A94(접근축 수평) | 각도를 세우면 **TCP 가 파지점보다 80 mm 위로** 올라가 정책이 다시 기욺 |
| 7 | 홈 교체 C96 / 라운드 30 고홈 | 고홈은 **정반대로** 나빠짐: 접근각 116° · 긁힘 42 배 |
| 8 | 액션 박스 `ey` 상한 (라운드 28) | fabric 이 위치·자세 상충 시 **자세를 조용히 포기**해 명령을 잘라도 안 따라옴 |

**실제 원인.** 파지점이 판 위 **47.5 mm** 로 낮아 팔이 과신전하고, 그 자세에서 fabric 이
회전을 버린다. 도달성 실측(접근각 ≤100° 를 만족하는 최소 접근거리, 문턱 22.5 mm):

| 파지점(판 위) | 최소 접근거리 | 판정 |
|---|---|---|
| 47.5 mm | 45.3 mm | ✗ 미달 |
| 100 mm | 20.9 mm | ✓ |
| 110 mm | 18.7 mm | ✓ |

**처방(E29).** `GRASP_HEIGHT_BAND` 를 판 위 **80~150 mm** 로 올렸다. **각도 보상은 하나도
넣지 않았다.** 접근각 118° → 97.9% · 긁힘 17 배 감소 · 성공은 B25 와 동등.

> **일반화.** 자세가 이상하면 자세를 벌하기 전에 **기구학이 그 자세를 강제하고 있는지**
> 부터 본다. 보상으로 기구학과 싸우면 정책은 과제를 버리는 쪽으로 도망친다.

## 기각 목록 — 되살리지 말 것

### 보상
- **`still_shaped`(라운드 14 감속 셰이핑)** — `P_DIST_BAND` 재사용이 결함이었다.
- **`still_at_goal`(라운드 16 목표 안 안정화)** — 채택 안 됨.
- **`still_net`(순변위 속도 입력, 라운드 3 arm B)** — 제자리 왕복에 만점. 순간속도로 확정.
  반환점에서 순간속도가 0 이 되는 문제는 `P_still` 을 `P_dist` 와 **곱해서** 막는다.
- **`R2 speed_scale_from_dist`** — 제자리 왕복이 순변위 0 으로 점수를 벌었다.
- **`GRASP_OFFSET_ROOT` z +30 mm** — 목표가 도달 봉투 위로 밀려 이득 없음. z +12 mm 확정.
- **tip 마진 35 mm(A26)** — 긁힘 4.8% → **36.4%**(7 배 악화). 마진이 작동점 밖으로 나가면
  힌지가 상시 켜진 **상수 벌점**이 되어 기울기가 사라진다. 안전 구간은 27~32 mm.
- **dwell 증가(E26)** — 250 스텝 에피소드에서 "잡고 버티기"로 파지 보상 5 배 수확.

### 제어·리셋
- **홈 후보 J147 · A94 · C96 · 고홈(라운드 30)** — B100 이 이겼다. 홈은 **첫 프레임만**
  정하고 그 뒤는 fabric 이 액션 박스 중심(접근각 94.99°)으로 끌고 간다. 홈이 실제로
  바꾸는 것은 fabric 의 **널스페이스 앵커**(= IK 가지 선택)다.
- **`anchor_relatch`(env 별 cspace 재앵커)** — 채택 안 됨.
- **`kd_r2s` 브래킷** — 좌팔 여진 측정이 없어 판단 근거 없음. 벤더 kd 로 확정.
- **`action_rate` 커리큘럼** — t73/t75 가 발동 시점(ep1500)에 정확히 꺾였다.

### 계측
- **제약 IK 스폰 프로브(`probe_grip_l_spawn_ws_ik.py`)는 오라클로 못 쓴다.** 정책이 파지
  실패 0.5% 로 잘 잡는 박스를 "전부 실패"로 찍었다. 봉투는 **정책으로** 잰다.
- **관절 전범위 균일 샘플**은 정책 분포가 아니다 — 없는 문제를 만든다.

## 09.03 정리에서 실제로 잡은 결함 3 건

정리는 주석만 건드린 게 아니라 **살아 있는 위험**을 드러냈다.

1. **`CUP_ORIGIN_TO_GRASP_Z` 가 대역 파생값이었다.** 대역을 v2 로 옮기면서 이 파생을 같이
   안 옮겼으면 파지 조준점이 **67 mm** 어긋난다(−44.6 mm vs +22.9 mm).
2. **그리퍼 액션 게이트도 `grasp_ok` 를 쓴다.** 보상만 새 대역으로 바꾸면 "보상은 받는데
   그리퍼가 안 열리는" 상태가 조용히 생긴다. 이제 `grasp_band` 를 게이트에도 넣는다.
3. **환경변수가 v1 모듈 상수를 통째로 덮어썼다.** `HDGP_BAND_LO/HI` 는 같은 프로세스의
   v1 트랙까지 오염시킨다. 대역을 **호출 인자**로 바꿔 트랙 격리를 회복했다.

또한 **파지 대역이 `env.yaml` dump 에 남지 않았다** — E29 의 결정적 설정이 실행 스크립트
에만 있었다. 이제 `actions.gripper_action.grasp_band` 로 덤프에 기록된다.

## 09.03 — G/H 시리즈: 재소환 제거 이후 (사용자 결정 "리프트만 · 재소환 없음")

**폐기 근거.** 재소환(`respawn_cup`)이 전도 비용을 0 으로 만들어 정책이 "밀어 넘어뜨리고 다시
시도"를 학습했다 — E29 84% · B25 90% 가 컵을 60° 이상 넘어뜨리고 에피소드당 3~4회 재소환.
실기의 접근→전도→후퇴→재접근 궤적의 원인. 재소환 체제 체크포인트 45개 격리
(`log/checkpoints_deprecated_respawn/`). **KUKA 게인**(kp 300/kd 45, 실기 kp 70/kd 2.75) 학습판
(fab 전 계열·t79)도 실기 제어 불가로 실격 — kd 최대 30배.

| 판 | 변경 | 결정론 실측(학습 호스트) | 결론 |
|---|---|---|---|
| G1 | 재소환 끔 | r_grasp 0.765 · **r_lift 0.011** | 잡고 안 든다 — 재소환이 탐색 보조였다 |
| G2 | + 리프트 전용(계단 2단) | 리프트 체류 발화 · **접근각 145°** | 국소최적은 풀렸으나 위에서 내리꽂음 |
| G3 | + 회전 박스 ±25° | 파지 96.7% · 리프트 68.6% · 긁힘 0% · **입구 파지** | ep1400 정점 후 붕괴(3000ep) |
| G4 | 대역 45~105 · 1600ep | 리프트 84% · 옆구리 · **손끝 14mm** | 옆구리는 됐는데 긁는다 |
| G5 | 박스 ±15° | G4 와 **모든 지표 동일** | 박스는 손잡이가 아니다 |
| H2 | 대역 60~120 | 리프트 93% · 손끝 14mm · **파지 TCP 49mm** | 하한에 붙어 잡는다 |
| H3 | 대역 75~135 | 리프트 94% · 손끝 13mm · **파지 TCP 68mm** | 〃 (마지막 검증 설정) |

**확정된 사실.**
1. **접근각은 손잡이가 아니다** — 박스 ±25°↔±15° 에서 모든 지표 동일, `ey_mu` 음수(정책이
   이미 세우려 함)인데 실측 115° 고정. 달성 자세는 지령이 아니라 fabric·기구학이 정한다.
2. **정책은 대역 중앙이 아니라 하한에 붙어 잡는다** — 하한 +7~17mm. 하한이 파지 높이를 1:1 지배.
3. **긁힘(손끝 14mm)은 파지 순간이 아니라 접근 중 훑기다** — 파지는 49~68mm 에서 일어나
   `tip_floor` 마진(30mm) 위다. 따라서 벌점 상향이 파지와 상충하지 않는다(앞선 기각 철회).
4. **위/옆 접근은 양자택일** — 하한 80mm(G3)에서 위-접근(TCP 199mm, 안 긁음, 입구, 리프트 68%)
   으로 뒤집힌다. 75mm 이하는 옆-접근(긁음, 옆구리, 리프트 84~94%).
5. **프로브는 학습한 호스트에서** — 같은 체크포인트가 RTX 5090 vs RTX PRO 6000 에서
   grasp_ok 0.000 vs 0.144 로 갈렸다(원인 미규명). 자산·코드·체크포인트 전부 동일 확인.
6. hydra 오버라이드는 `__post_init__` 에 안 닿는다 — F2 가 사다리 켠 줄 알고 E29 재실행이 됐다.

**다음 판(I1, 준비 완료 · 미실행).** H3 설정 + `TIP_FLOOR_WEIGHT` −6 → −12 (2단 한 칸 15 미만,
reward-audit ACCEPT — Check 3 은 파지 순간 실측으로 해소). 목표: 옆구리 파지·리프트 94% 를
유지하면서 접근 훑기만 억제해 손끝 ≥30mm.

**현재 자산(로컬 `log/checkpoints_keep/`, git 미추적).**
