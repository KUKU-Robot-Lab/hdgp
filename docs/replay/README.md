# 재생 레시피 — dirty 트리 위에서 학습된 정책을 되살리는 법

## 왜 있나

이 저장소는 학습 실험 루프라 **미커밋 상태로 학습하는 일이 흔했다.** 그 위에서 나온
체크포인트는 나중에 재생이 안 된다 — 커밋만 맞춰도 코드가 다르기 때문이다.
`m1_final` 이 그렇게 죽었다(성공 0.94~0.98 로 기록됐는데 현 소스에서 0/1024).

여기 있는 패치는 그 dirty 상태를 **git 안에 고정**해 재생을 영구히 가능하게 만든다.

## `b1_0293644_dirty.patch`

`s2r_b1_anylink` 학습 시점의 미커밋 변경 7파일. 배포 후보
`_DEPLOY/b1_ep12000.pth`·`b1_ep10800.pth` 와 `sim2real/logs/policy/right_b1/` 이
이 코드 위에서 학습됐다.

★출처는 worktree `~/rl_ws/hdgp_b1`(커밋 `0293644` 고정) 이었다. 2026-09-01 에
worktree 를 정리하면서 그 dirty 상태를 패치로 떠서 여기 남긴다 — worktree 는
언제든 재생성할 수 있지만 그 안의 미커밋 변경은 지우면 끝이기 때문이다.

### 재생 방법

```bash
git worktree add ~/rl_ws/hdgp_b1 0293644
cd ~/rl_ws/hdgp_b1 && git apply ~/rl_ws/hdgp/docs/replay/b1_0293644_dirty.patch
```

★추가로 필요한 것: `assets/env/usd/env_rigid.usd`. 학습 당시에는 **미추적**이었고
2026-09-01 커밋 `b633457` 로 저장소에 들어왔으므로, 위 worktree 체크아웃(0293644)
에는 없다. 본진에서 복사해 넣어야 한다.

★`test_history.md` 의 "uncommitted 변경 없음" 기록은 **거짓**이다 — 이 패치가 그
반증이다. 스냅샷 기록을 믿지 말고 이 패치를 진실원천으로 쓸 것.

## 새 항목을 추가할 때

dirty 상태로 학습한 체크포인트를 배포 후보로 올릴 때는 **그 시점에** 패치를 떠서
여기 넣는다. 나중에 뜨려 하면 이미 트리가 굴러가 있어 못 뜬다.
