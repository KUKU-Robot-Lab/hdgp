# IKER VLM 키포인트 보상 프레임워크 — hdgp 설계

- 날짜: 2026-09-13
- 상태: 설계 승인 완료(섹션 1~5, 채팅), 문서 검토 대기
- 목적: IKER(VLM-Generated Iterative Keypoint Rewards) 방식 **단독**의 성능을 우리 로봇·환경에서 잰다.
  hdgp 의 text2reward(t2r) 트랙과 **분리**한다 — t2r 코드를 import 하지 않는다.
- 연산 자원: **로컬 GPU 만** 사용한다(서버 미사용).

## 1. 범위

포함
- 머리 카메라 스냅샷 → 키포인트 표시 영상 → VLM 상호작용 코드 → 게이트 → 고정 IKER 보상으로 RL 학습 → 평가.
- 시범 과제: 단일 단계 신발 놓기(IKER shoe placement 재현), 오른팔 `tesollo_right`(DG-5F).
- VLM 백엔드 두 종: Claude Code(당장 사용), Qwen3-VL(배선과 가짜 전송 테스트까지).
- 평가: 시작·목표 구성 10개 × 환경 128개, VLM 생성 대비 사람 기준선.

제외(이번 설계 밖)
- 다단계 실행(프롬프트 형식과 이력 구조만 준비), 실기 배포, 실제 장면 재구성(BundleSDF·FoundationPose).
- 파지 동작 학습(시작 파지는 뱅크로 준다 — IKER 원형과 같다).

## 2. IKER 원형 — 논문으로 확인한 사항

출처: 논문 PDF 본문 III 절·부록 A~C(텍스트 추출 `~/rl_ws/our_source/iker_render/probes/iker_paper_text.txt`), 공개 레포 `repo/skill_gen/IKER`.

| 항목 | 논문·레포 내용 |
|---|---|
| VLM 입력 | 지시문, 번호가 찍힌 키포인트 영상, 이전 영상·코드 이력(다단계). 예시 없음 |
| VLM 출력 | `get_interaction_data(keypoint_coordinates)` — 상호작용 물체, 키포인트 번호, `grasp_mode`, 다른 키포인트 기준으로 계산한 최종 좌표, `done` |
| 보상 | **고정식** `α_dist r_dist + α_dir r_dir + α_align r_align + α_bonus r_bonus + α_penalty r_penalty` — VLM 은 목표만 정한다. 초록의 "보상 함수 생성" = 목표 계산 코드 + 고정 항 |
| 키포인트 | 메시 기반. 움직이는 물체는 중심 기준 축 끝점, 고정 물체는 표면 균일 분포. 물체별 번호, 투영 겹침 시 고정 물체 점 먼저 제거·물체끼리는 낮은 번호 유지 |
| 반복 | 다단계 계획 — 단계마다 재질의, `done=True` 로 종료 |
| 파지 | sim 은 휴리스틱 파지 + 노이즈, 실기는 AnyGrasp. 학습하지 않는다 |
| 상태·액션 | 상태 = (끝단 자세, 물체 자세, 물체 키포인트, 목표 키포인트), 액션 = 끝단 자세 변화량, 10 Hz |
| 평가 | 구성 10개 × 128 env = 1280 시행. **성공 = 평균 키포인트 거리 5 cm 이내** |
| 신발 놓기 수치 | 사람 라벨 sim 0.945 / 실기 0.8, VLM(GPT-4o) sim 0.778 / 실기 0.7 |

★공개 데이터 결함: 목표 키포인트 간격(0.150/0.100 m)이 추적 오프셋(0.24/0.15 m)과 다르다. 평평한 테이블에서는
어떤 신발 자세로도 성공 판정을 통과할 수 없었다(최선 정규화 오차 0.117·정지 자세 0.217 > 0.10). VLM 이
강체 조건을 어긴 목표를 줄 수 있다는 뜻이므로 **도달성 게이트가 필수**다(§6).

## 4. 장면과 키포인트

장면(로봇 원점 = 마운트 플레이트 상면, m)

| 요소 | 값 |
|---|---|
| 테이블 | env_v1, 상면 z 0.205 |
| 받침 | 운동학적 박스, x 0.11~0.43 · y −0.33~0.03 · 상면 z 0.325(높이 0.12) |
| 다른 신발 | 받침 위 (0.27, −0.15), 긴 축 world x |
| 옮길 신발 시작 | 테이블 위 (0.27, +0.14), 긴 축 world x |
| 신발 자산 | IKER `object_0/1` 메시 → USD, 밀도 100, convex hull 충돌체 |

- 받침 양쪽 자리(다른 신발 ±0.129 m)는 모두 받침 위이고 오른팔 도달 영역(y ≤ 0.22) 안이다. 좌우 선택은 VLM 이 한다.
- 받침 폭 0.36 m 는 두 자리를 담는 최소 폭이라 다른 신발 y 는 −0.15 로 고정된다.
- 이 배치는 머리 카메라 화각 제약으로 정했다(§14). 받침 0.203 m·폭 0.40 m 원안은 한 장에 담을 수 없었다.

키포인트
- 움직이는 물체(두 신발): **정지 자세에서 수평인 두 로컬 축**의 메시 끝점 4개. 신발은 로컬 z(길이, ±0.125)와 로컬 x(너비, ±0.048)이고 로컬 y 가 수직이다.
  크기 순서 규칙("가장 긴 두 축")은 높이축(0.104 > 너비 0.096)을 고르므로 쓰지 않는다. 오프셋은 메시에서 계산한다.
- 고정 물체(받침): 상면 3×4 격자, 가장자리에서 0.05 m 안쪽. env_v1 테이블 면에는 두지 않는다.
- 번호: **회전 후 영상**에서 왼쪽에 있는 움직이는 물체부터 4개씩, 고정 물체는 그 뒤. 옮길 물체를 1번부터 주지 않는다.
- 가림: 투영 깊이가 렌더 깊이보다 1 cm 넘게 뒤면 가려진 점으로 표시(회색). 화면 밖 점은 그리지 않는다.
- 겹침: 투영 거리 15 px 미만이면 고정 물체 점을 먼저 지우고, 물체끼리는 낮은 번호를 남긴다(15 px 는 설정값).
- VLM 코드 입력: `{"1": np.array([x, y, z]), ...}`, 로봇 기준 좌표. 보상과 같은 좌표계.

## 5. 스냅샷(카메라)

1. 구성으로 리셋, 머리 **pan −20° · tilt −20°(인코더)** 를 매 물리 스텝 재지령(한 번만 쓰면 스텝당 1.6° 씩 0 으로 끌려간다).
   각 규약: tilt 0 = 바로 아래, 음수 = 테이블 쪽, 음수 pan = −y.
2. 정착 후 RGB·깊이 렌더(640×480).
3. **카메라 자세 = `head_camera` 링크 자세 ⊗ `sim2real/config/head_camera_sim.json` 오프셋(ROS 광학 규약)**.
   Isaac Lab `Camera` 센서의 `pos_w`/`quat_w_ros` 는 0·NaN 으로 남으므로 쓰지 않는다(hdgp `render_pass.py` 와 같은 우회).
   내부 파라미터는 렌더러가 보고한 값(fx·fy 평균, 주점 = 영상 중심).
4. 키포인트 투영·가림·겹침(§4).
5. world +x 투영 방향이 영상 위쪽이 되도록 **매 스냅샷 회전각을 계산**해 회전 후 640×480 로 자른다(채택 자세 실측 −20.8°).
   이렇게 해야 논문 프롬프트의 "+x 위·+y 왼쪽" 문장이 참이 된다.
6. 번호 원·오른쪽 아래 좌표축 범례를 그려 `snapshot.png`, 원본 `snapshot_raw.png`, `keypoints.json`(번호·물체·world·화소·가림) 저장.
7. 검증 조건: 모든 키포인트가 회전 후 화면 안 여유 ≥ 15 px, 카메라 자세·내부 파라미터 유한값. 어기면 중단.

## 6. VLM 생성·수집·게이트

프롬프트
- 논문 부록 C 단일 단계 프롬프트를 **글자 그대로** 쓰고 `[TASK]` = "Place the shoe on the rack next to the other shoe.", 영상 1장.
- 다단계 프롬프트도 원문으로 보관하고 이전 영상·코드를 붙이는 형식만 구현한다(이번 시범에서는 쓰지 않음).

백엔드 인터페이스: `generate(prompt: str, images: list[bytes]) -> str`
- Claude Code: `iker_runs/.../attempt_NN/` 에 `prompt.md`·`snapshot.png` 를 쓰고, 세션이 **새 에이전트에게 그 두 경로만** 준다.
  에이전트는 영상을 보고 `response.md` 를 쓴다. 저장소 탐색 금지 — 설계 의견이 생성기에 섞이지 않게 한다. 절차는 `scripts/iker/GEN_PROMPT.md`.
- Qwen3-VL: 기존 `source/vlm` Qwen 코드(영상 1장·출력 256 토큰·붓기 해석 전용)를 확장한 새 엔드포인트
  `/v1/generate`(system·prompt·여러 장 base64 영상·`max_new_tokens`). 모델 id 설정 가능. 가짜 전송 테스트까지 하고, 가중치 내려받기는 별도 결정.

수집
- 응답에서 파이썬 코드 블록 하나를 뽑는다. 구문 검사: import 는 numpy 만, `open`·`exec`·`eval`·`__import__`·속성 우회 금지.
- numpy 만 있는 이름공간에서 실행 → `object_to_interact`, `keypoint_indices_to_interact`, `grasp_mode`, 좌표, `done`.

게이트(프롬프트는 바꾸지 않는 기계적 검사)
- G1 실행 성공, 반환 형식 일치, `done=False`.
- G2 번호가 모두 존재하고 **한 움직이는 물체**에 속한다.
- G3 목표 좌표가 유한값. 물체 키포인트를 목표에 최적 강체 정합(Kabsch)해 잔차를 기록한다.
- G4 최적 정합 자세에서 **평균 키포인트 거리 ≤ 5 cm**(평가 기준)이고 정규화 오차 ≤ 0.10(학습 성공 보너스 기준).
- G5 최적 정합 자세의 메시 최저점이 테이블·받침 면을 1 cm 넘게 뚫지 않는다.
- G6 최적 정합 자세 중심이 오른팔 도달 영역(프로필 `palm_box`) 안.
- G7 `grasp_mode=False` 인데 목표가 시작 지지면보다 2 cm 넘게 높으면 실패(밀어서 올릴 수 없다).
- 실패 시 **같은 프롬프트로 최대 2회 재생성**(오류 문구를 붙이지 않는다 — IKER 원형 유지). 그래도 실패면 중단·보고.
  모든 시도·게이트 수치를 저장하고 **게이트 실패율을 VLM 품질 지표로 보고**한다.

결과 파일 `interaction_<vlm|human>.json`: 물체, 번호, grasp_mode, 목표 world 좌표, 물체 로컬 키포인트, 게이트 수치, 스냅샷 경로.

사람 기준선: IKER 공개 데이터의 목표 관계(다른 신발 기준 목표 위치)를 가져와, 우리 키포인트 오프셋에 **최적 강체 정합한 자세**의
키포인트로 만든다. 원 데이터의 간격 불일치를 그대로 옮기면 기준선부터 도달 불가능해지기 때문이다. 같은 게이트를 통과해야 한다.
정합은 방향(요)과 위치만 맞추고 기울기는 스냅샷에서 **안착한 자세 그대로** 둔 뒤 받침 위에 내려놓는다 — 스캔 메시 밑창이
평평하지 않아 받침 위 신발이 4~5° 기운 채 안착하는 것을 프로토타입 스냅샷에서 확인했다(2026-09-13).

| 종료 | 200 스텝(20 s), 성공(정규화 오차 ≤ 0.10)·실패(낙하) 각각 **누적** 21 스텝 — 레거시 카운터는 에피소드 안에서 줄지 않는다(연속 아님, `shoe_place.py:760·764·632`) |
| 목표 | 환경 하나 = 결과 파일 하나(구성 하나) |
| PhysX | `gpu_collision_stack_size` 2^29, `gpu_max_rigid_patch_count` 2^23, `gpu_max_rigid_contact_count` 2^24 |

도메인 무작위화(레거시 코드 값)
- 신발 질량 ×0.3~2.0, 마찰 ×0.3~1.8, 반발 +0~1, 무게중심 ±0.025 m.
- 시작 위치 xy ±0.02 m·z 회전 ±0.2 rad(옮길 신발), ±0.01 m·±0.05 rad(다른 신발).
- 관측 가산 노이즈 ±0.02, 액션 가산 노이즈 ±0.05, 관측 쿼터니언 ±0.2 rad 회전 노이즈 + **쿼터니언 전체 부호 뒤집기**(§13 편차).

PPO(레거시 ShoePlacePPO)
- MLP 256·128·64 ELU, 공유 백본, `fixed_sigma` 초기 0, 입력 정규화 끔·가치 정규화 켬, value bootstrap.
- γ 0.99, τ 0.95, 학습률 5e-4 adaptive(kl 0.008), horizon 32, **minibatch 16384**, mini-epoch 5, e_clip 0.2, critic 4, grad_norm 1.0, bounds_loss 1e-4.
- 환경 4096개, **max_epochs 250**(레거시 예산 10240×32×100 = 3,280만 프레임과 동일).

## 8. 파지 시작 상태

파지 뱅크 생성(`scripts/iker/make_grasp_bank.py`)
1. 손 편 자세(프로필 `hand_open_pose`)로 손바닥을 신발 위에 둔다. 엄지와 나머지 손가락이 너비 방향을 사이에 둔다.
2. 편 자세 → 쥔 자세(`hand_grip_pose`) 보간으로 닫고, 막힌 관절은 동결한다(grasp_s2r 시너지와 같은 방식, 코드는 import 하지 않고 태스크 안에 둔다).
3. 손바닥을 0.05~0.10 m 들어 1~2 s 유지. 신발–손바닥 상대 위치 변화 < 1 cm 인 것만 성공.
4. 기록: 팔·손 관절 **지령값과 측정값**, 손바닥 기준 신발 자세, 생성 게인·솔버·dt 메타데이터. **관절은 이름으로** 저장한다.
5. 사전 자세(길이 방향 위치·높이·요)를 흔들어 64개 이상 모은다. 논문의 파지 노이즈(±0.01 m·±0.2 rad)는 이 다양성으로 구현한다.

리셋
- 뱅크에서 하나를 뽑아 관절 상태를 쓰고, 손 목표 = 기록된 **지령값**(에피소드 내내 고정), 신발 = 손바닥 자세 ⊗ 상대 자세.
- 뱅크 메타데이터의 게인이 학습 게인과 다르면 부팅 거부(측정값을 목표로 쓰면 파지력 0 — hdgp warm 뱅크 사고).
- `grasp_mode=False`: 손을 쥔 자세로 닫고 홈에서 시작(이번 시범에서는 G7 로 걸러져 쓰이지 않는다).

## 9. 평가 프로토콜

- 구성 10개: 고정 시드로 옮길 신발 시작 (x 0.22~0.32, y 0.12~0.16, 요 ±10°)과 다른 신발 x(0.25~0.29)를 뽑는다.
  다른 신발의 y(−0.15)와 요(0°)는 고정한다 — 받침 폭 0.36 m 가 곧게 놓인 두 자리의 최소 폭이라, 5° 만 돌아도 옆자리 신발이 받침 끝에서 약 1 cm 삐져나온다.
  각 구성은 §5-7 스냅샷 조건과 장면 안착을 통과해야 하고, 못 하면 같은 시드 흐름에서 다시 뽑는다.
- 구성마다: 스냅샷 → VLM 결과·사람 결과 → 게이트 → **각각 학습**(구성별 정책, 논문 방식) → 환경 128개로 평가.
- 성공: 에피소드 끝 평균 키포인트 거리 ≤ 5 cm. 학습 내부 성공(정규화 0.10)은 별도로 기록.
- 보고: 구성별·전체 성공률(VLM·사람), 게이트 실패율, 학습 곡선, 소요 시간. 논문 수치는 조건(GPT-4o·xArm·실제 장면)이 달라 참고로만 둔다.
- 시간 예산: 학습 1회 약 1.3 h(4096 env, 초당 약 7,000 프레임 실측), 20회 순차 약 26 h(로컬).

## 11. 오류 처리

- 생성 실패(코드 없음·실행 오류·게이트 실패): 같은 프롬프트로 최대 2회 재생성 후 중단·보고, 모든 시도 저장.
- 카메라 자세·내부 파라미터·키포인트가 유한값이 아니면 즉시 중단. 가드는 NaN 이 통과하지 못하는 양의 형태로 쓴다.
- 파지 뱅크 게인 불일치 → 부팅 거부.
- hdgp 경로·프로필·자산 누락 → 무엇이 없는지 적은 메시지로 중단.
- 편집 후 실행 단계는 편집 성공과 새 내용 표식 확인에 묶는다.
