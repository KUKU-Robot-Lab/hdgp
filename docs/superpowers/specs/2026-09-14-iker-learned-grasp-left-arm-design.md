사용자 결정(2026-09-14):
1. IKER 원형 유지 — 보상 5항 고정, VLM 은 목표 코드만, "반복"은 단계마다 새 관측으로 재질의(논문 III 절·Algorithm 1).

4. K1 스크립트 파지 대신 **파지부터 학습**한다 — 2단계: 파지 정책 → IKER 정책.
5. 2단계 IKER 정책의 손은 1단계 파지 목표에 **고정**하고 행동은 팔 6차원(원본 IKER 과 같다).

8. reward-audit 수정(§12)을 확인하고 진행한다.
9. **K1 뱅크를 왼팔로 다시 만들지 않는다** — 파지는 학습으로 배운다.
10. **q 보정은 1단계 A 단계(g(q) 끔)에서 잰다** — 들기 시작한 체크포인트의 래치·성공 순간 q 로 q_lo·q_hi 를 정하고

## 5. 파지 품질 q

- 손가락마다 마디 링크 `<side>_hl_<f>_3`·`_4`·`_tip`(프로필 `finger_sensor_bodies`)의 위치에서 신발 표면점(`shoe_meta.json`
  `hull_local` 1,776점에서 균일 간격 256점)까지 **최근접 거리** d_l.
- 커널 k_l = exp(−d_l / 0.02), 손가락 평균 w_f, 5손가락 soft-min(τ 0.1), 손바닥 링크 +x(쥐는 쪽)가 신발 중심을 향할 때만
  (cos > 0).
- g(q) = g_min + (1 − g_min)·clip((q − q_lo)/(q_hi − q_lo), 0, 1).
- **A 단계**: g_min = 1.0(g ≡ 1). q 는 매 스텝 로깅만 한다.
- **보정**(관찰 대조 12행 — 컵 값을 신발에 쓰지 않는다): A 단계에서 래치 비율이 10 % 이상인 체크포인트를 결정론으로 굴려
  래치·성공 순간 q 를 64 개 이상 모으고, q_lo = p25·q_hi = p90 를 `grasp_quality_calibration.json` 에 적는다
  (`scripts/iker/measure_grasp_quality.py --checkpoint`).
- **B 단계**: g_min = 0.5 로 A 체크포인트에서 이어학습한다. g_min < 1 이면 env 가 보정 파일을 요구한다(없으면 부팅 오류).
- 연산량: 4096 env × 15 마디 × 256 점 = 1,570 만 거리/스텝 — 학습 스모크에서 fps 를 잰다.

## 6. 1단계 보상·종료

**자유 들기 높이** dz_free = 신발 hull 최저점 z − 에피소드 시작 시 최저점 z. 신발 hull 256점의 xy 가 받침 영역을
**1 cm 여유**로 넓힌 사각형과 하나라도 겹치면 **0** — 받침에 밀어 올리거나 옆면에 기댄 높이를 들기로 세지 않는다.

**잡힘** held = dz_free ≥ 0.05 ∧ 손바닥–신발 중심 거리 ≤ 0.15 m ∧ |신발 속도 − 손바닥 속도| < 0.05 m/s.

| 항 | 식 | 비고 |
|---|---|---|
| palm_progress | 50 × (손바닥–신발 표면 간극의 에피소드 최단거리 갱신분), 래치 전 | 진행형, 에피소드 예산 ≤ 5 |
| lift_progress | 2000 × (clamp(dz_free − 0.01, 0, 0.04) 의 에피소드 최고치 갱신분), 래치 전 | 진행형, 총액 80. 1 cm 불감대: 정착 자세에서 신발 표면점이 테이블 아래 4 mm 에 있고 반발계수가 최대 1 이라 리셋 때 신발이 몇 mm 튄다(미러 스모크 무행동 9.2 → 0) |
| lift_bonus | 300 × g(q), **잡힘 3 연속 스텝** 순간 1회(래치) | 한 프레임 튕김으로 못 받는다 |
| success_bonus | 1000 × g(q), 잡힘 20 연속 스텝 ∧ 신발 속도 < 0.05 m/s 순간 1회 → 종료 | 끊기면 카운터 0 |
| hand_floor | −10 × (테이블 + 1 cm 아래 손 최저점 깊이), 스텝당 상한 5 | |
| arm_vel · hand_vel | **0**(첫 런). Σ\|q̇\| 원시값만 로깅 | 과제 전 억제 항 금지 |

- 잘림: 120 스텝, value bootstrap. 종료: 성공, 또는 신발이 테이블 아래로 떨어짐(z < 0.10) — 벌점 없음.
- 무행동 수입: 스텝 수입 상수 항은 없다. 영행동에서 팔이 약 1 cm 처지면 palm_progress 래칫이 한 번 ≈ 0.6 을 준다(에피소드 상한 = 시작 간극 × 50 ≤ 7, 스텝마다 쌓이지 않는다 — IK 상대 명령 0 은 목표를 현재 자세로 다시 잡아 처짐을 되돌리지 않고, 2단계 env 도 같다). 스텝 40 에 래치·60 에 성공하면 할인 가치 ≈ 0.99⁴⁰·(80 + 300·g) + 0.99⁶⁰·1000·g
  (A 단계 g = 1: ≈ 801, B 단계 평손 g = 0.5: ≈ 428).
- 래치 뒤 유지 구간의 스텝 수입은 0 이고 성공까지 기다리면 1000·g·0.99²⁰ ≈ 818·g — "보너스만 받고 놓기"보다 유지가 낫다.
- 로깅(관찰 대조 17행): 부팅 때 적용 보상 설정·무행동 스텝 수입(0 이 아니면 부팅 오류). 스텝마다 보상 항·q·손가락별 w_f·
  손바닥 cos·dz_free·잡힘 비율·래치 비율·받침 위 들림 비율(해킹 감시)·팔/손 Σ|q̇|. 에피소드 끝 성공·래치·최고 들기·래치/성공
  순간 q.

## 7. 학습 파지 뱅크 (계획 2c)

- 1단계 체크포인트를 결정론으로 롤아웃하고 성공 순간의 전 관절 위치·관절 목표(팔 = 현재 자세, 손 = EMA 목표)·신발 자세·
  손바닥 자세를 기록한다.
- 기존 `make_grasp_bank.py` 의 재현 들기 검증(상태 복원 → 손 고정 → 10 cm 들기 → 1 s 유지, 신발–손바닥 상대 변화 < 1 cm)을
  통과한 것만 넣는다. 최소 64 개.
- 스키마·부팅 대조는 그대로, `metadata.source = "learned_grasp"`·`side_sign`·체크포인트 경로·sha256·1단계 보상 버전을 더한다.
- 함정: 관절 열은 **이름**으로 정렬하고, 1단계와 2단계는 같은 게인·같은 자산이어야 한다. 부팅 대조가 게인을 검사한다.

## 8. 2단계 IKER 정책 (계획 2c)

- 기존 `IkerShoeEnv` 그대로: 행동 6D, 손 = 뱅크 손 목표 고정, IKER 보상 5항·종료 그대로.

## 9. 평가·판정

- 1단계 게이트: A 단계 epoch 100 에 에피소드 래치 비율 < 2 % 면 설계 문제로 멈추고 보고한다. 받침 위 들림 비율이 오르면
  해킹 의심으로 보고한다.
- q 보정 시점: A 단계 에피소드 래치 비율 ≥ 10 % 인 첫 저장 체크포인트.
- **첫 성공 체크포인트에서 영상으로 파지 형태를 본다**(관찰 대조 7·9행 — 스칼라 성공 지표는 스스로를 감사하지 못한다).
- 1단계 결정론 평가(512 env·첫 에피소드): 성공률, 성공 순간 q·손가락별 w_f, 들었다 놓침 비율, 받침 겹침 비율.
- 2단계(계획 2c): 기준 스펙 §9 평가 + 결정론 프로브. 비교 기준 = 오른팔 K1 ep250 26.8 %·ep750 29.3 %.
